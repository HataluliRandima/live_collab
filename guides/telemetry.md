# Observability with Telemetry

LiveCollab emits [`:telemetry`](https://hexdocs.pm/telemetry) events for
sessions, presence rebuilds, locks, dropped or rejected client events, and
spotlight changes. See `LiveCollab.Telemetry` for the full event reference.

## Why it matters

Collaboration state lives in many independent LiveView processes. Without
instrumentation, you cannot tell:

* that a client is flooding cursor events and being rate limited;
* that someone is sending malformed or hostile payloads;
* how often concurrent edits collide on the same field;
* how expensive presence rebuilds have become as a room grows.

## Logging in one line

```elixir
# lib/my_app/application.ex
def start(_type, _args) do
  LiveCollab.Telemetry.attach_default_logger()
  # ...
end
```

This logs rejected payloads and unauthorized spotlight attempts at `:warning`,
the first and then every 1000th rate-limited event of a flood at `:warning` (a
flooding client cannot flood your logs), lost locks at `:info`, and session and
lock activity at `:debug`. Client payloads are never logged.

## LiveDashboard metrics

Add to `metrics/0` in your `MyAppWeb.Telemetry` module (generated by
`mix phx.new`):

```elixir
# Security / abuse
counter("live_collab.event.rate_limited.count", tags: [:event, :bucket]),
counter("live_collab.event.rejected.count", tags: [:event, :reason]),
counter("live_collab.spotlight.unauthorized.count", tags: [:action]),

# Collaboration health
counter("live_collab.lock.claimed.count"),
counter("live_collab.lock.denied.count"),
counter("live_collab.lock.lost.count"),

# Room cost
summary("live_collab.presence.sync.duration", unit: {:native, :millisecond}),
summary("live_collab.presence.sync.metas"),
summary("live_collab.presence.sync.coalesced_diffs")
```

`presence.sync.metas` is the number of connected clients in the room, and
`presence.sync.duration` is what one rebuild costs one LiveView. Their product,
times the rebuild rate, approximates the room's CPU cost.

Avoid `:topic` or `:client_id` tags unless your metrics backend can handle one
time series per document or per browser tab.

## Custom handlers

```elixir
:telemetry.attach(
  "alert-on-flood",
  [:live_collab, :event, :rate_limited],
  fn _event, _measurements, %{consecutive: n} = meta, _config ->
    if n == 500, do: MyApp.Alerts.notify("client #{meta.client_id} is flooding #{meta.topic}")
  end,
  nil
)
```

Handlers run synchronously in the LiveView process that emitted the event, so
keep them fast and never raise. `:telemetry` detaches a handler that raises.
